## 1. 架构

| 层 | 位置 | 说明 |
| --- | --- | --- |
| Go 核心 | `core/`（与另两端相同） | `cmd/cbcore-dll` 编成 `libclipbridge_core.dylib`：zig 作为 C 工具链，`macos/sdk-stubs/*.tbd` 代替苹果 SDK |
| 共用逻辑 | `windows/ClipBridge.Windows/Logic/*.cs`、`Strings*.cs`、`Interop/CoreInterop.cs`、`Update/UpdateModel.cs`、`Update/BuildInfo.cs` | 以链接方式编进 Mac 工程，**不复制**。改 Windows 的逻辑或文案，Mac 跟着变。唯一排除的是 `DpapiKeyStore.cs` |
| Mac 平台层 | `macos/ClipBridge.Mac/Platform/` | 见下表 |
| Mac 控制器 | `macos/ClipBridge.Mac/MacController.cs` | 对应 Windows 的 `ShellController` 和 `ShellActions`，规则相同：事件泵线程只解析和转发，核心调用不在 UI 线程，剪贴板读写在同一个串行队列上。暂不含笔记和密码库 |
| 界面 | `macos/ClipBridge.Mac/Views/`、`App.cs` | 用 C# 代码构建界面，不写 XAML |

Mac 平台层：

| 功能 | 实现 | Windows 对应 |
| --- | --- | --- |
| 剪贴板 | `MacPasteboard`：通过 ObjC 运行时调用 `NSPasteboard`。每 0.5 秒比较一次 `changeCount`，变化了才在工作线程读取文本。写入时用 `CurrentHostOnly`，不经「通用剪贴板」同步到其他苹果设备，并加 `TransientType`（敏感内容再加 `ConcealedType`）。带 Concealed、Transient、AutoGenerated 标记的复制不会发出去（密码管理器的复制） | 剪贴板格式监听 + sequence number |
| 数据库密钥 | `MacKeyStore`：登录钥匙串里的通用密码 `ClipBridge`/`db-key`，经 `/usr/bin/security` 读写，所以条目的访问列表记的是系统工具，不是本应用。ad-hoc 签名每次都变，更新后读取也不会弹窗。数据库已存在而密钥缺失时报错，**不会新建密钥**。安全性与 DPAPI 相当：同一用户的进程都能读到 | DPAPI |
| 开机启动 | `MacAutoStart`：`~/Library/LaunchAgents/com.nightclip.clipbridge.plist`，执行 `open -g -a <bundle> --args --minimized` | 注册表 `Run` 键 |
| 通知 | `MacNotifier`：`NSUserNotificationCenter`。这个接口已被苹果标为弃用，但对打包好的 .app 仍然能弹出；点击通知只会把应用带到前台 | 托盘气泡 |
| 打开文件、在 Finder 中显示 | `MacOpen`：`/usr/bin/open`、`open -R` | `explorer /select` |
| 自更新 | `MacUpdateApplier`：用 `ditto -x -k` 解压到 `~/Library/Caches/ClipBridge/staging`，校验包里的 Info.plist 和可执行文件，再启动一个 sh 脚本。脚本等本进程退出，把旧 .app 改名为 `.old`，换入新的，失败就回滚，最后用 `open` 启动。.app 所在目录不可写时拒绝安装 | 辅助 exe 替换文件 |
| 目录 | 数据：`~/Library/Application Support/ClipBridge`；日志：`~/Library/Logs/ClipBridge`；下载：`~/Downloads/ClipBridge` | `%LOCALAPPDATA%` |

核心改动（提交 1e0df62，随 0.1.94 发布到 Android 和 Windows）：

- 新增平台 `macos`，有 `proto.KnownPlatform` 和 `DesktopPlatform` 两个判断。
- 桌面端（windows、macos）互相之间由设备 ID 小的一方拨号；Android 只拨出。
- macOS 的下载目录规则与 Windows 相同。
- 更新平台新增 `macos`。
- 两个旧壳的设备列表会显示「macOS」。

## 2. 构建和发布（都在 Linux 上）

```sh
make dist-macos                                   # → core/dist/clipbridge-macos.zip
scripts/release-local.sh --platform macos --notes "…"
scripts/release-local.sh --notes "…"              # all = android + windows + macos
scripts/probe-update.sh -c <旧号> -p macos         # 像已安装的应用一样检查线上包
```

需要这些工具：go、zig 0.17.0、dotnet 10、rcodesign 0.29.0、zip。zig 和 rcodesign 装在 `~/.local/opt`，`~/.local/bin` 里有指向它们的链接，见 plan §2.4。

## 3. 部署到用户的 Mac（经 SSH）

- 本机的 `~/.ssh/config` 里有 `Host mac`（用户 yangziyi，地址 100.89.80.40）。
- 安装：
  ```sh
  scp core/dist/clipbridge-macos.zip mac:clipbridge-install/
  ssh mac 'cd ~/clipbridge-install && ditto -x -k clipbridge-macos.zip . && rm -rf /Applications/ClipBridge.app && mv ClipBridge.app /Applications/ && open /Applications/ClipBridge.app'
  ```
  经 scp 传过去没有隔离属性。经浏览器下载的话，要先执行 `xattr -cr`。
- 看日志：`ssh mac tail ~/Library/Logs/ClipBridge/clipbridge.log`。
- 经 SSH 截屏没有屏幕录制权限，只能拍到壁纸和菜单。要远程看界面，需要用户给 `sshd-keygen-wrapper` 开屏幕录制权限。

## 5. 已知限制和待办

- **托管 dll 没被封进签名**：`codesign --verify --deep --strict` 不通过，只影响 Gatekeeper 评估，不影响运行和自更新。正式修法是调整包的结构（plan §2.4）。
- **通知点了没有动作**：只会把应用带到前台。要做「点通知直接复制」，需要给 `NSUserNotificationCenter` 写 delegate（用 ObjC 运行时动态建类）。
- **没有应用图标**：没有 .icns，Dock 里显示通用图标。
- **剪贴板只同步纯文本**，与 Windows 相同。
- **还没做的功能**：笔记、密码库（Windows 有）；拖文件到 Dock 图标；Services 菜单。
- **只支持 Apple Silicon**（arm64），最低 macOS 13。
- **自动更新**：只在 .app 中运行时才能安装；开发版和不可写的安装目录会提示用户手动安装。
