# ClipBridge 使用说明书

> 适用于本仓库当前版本。ClipBridge 在你自己的 Windows 电脑和 Android 手机之间同步剪贴板文本、传输文件。设备之间通过 Tailscale 直连，**不经过任何第三方服务器**。
> 诚实说明：开发机上没有 Windows 桌面和 Android 真机，两端界面和系统功能（托盘、剪贴板监听、通知、相机扫码、前台服务、MediaStore、后台读取、密码库、自动填充）已编译并有大量逻辑单测，但**尚未在真机上跑过**。第 12 节列出了建议你优先验证的地方；密码库和自动填充尤其请先用不重要的数据试用。

## 1. 它能做什么

| 功能 | 说明 |
| --- | --- |
| 剪贴板同步（文本） | 复制即自动广播到所有已配对设备；电脑上复制 → 手机前台时直接写入，否则通知；手机在打开应用时自动发送，也可通过按钮、分享菜单、通知或快捷设置磁贴手动发；可选“后台自动发送”（进阶，需一次性 ADB 授权） |
| 密码库 | 本机加密的 KDBX 4 密码/API 密钥/笔记；Windows 与 Android 界面；备份/恢复、TOTP、导入导出；可按设备开启同步；Android 自动填充 | 实验性：界面与真机行为尚未验证 |
| 文件传输 | 双向，默认上限 4 GiB，断线自动续传，收齐后校验 SHA-256 才保存 |
| 配对 | 一次性二维码/链接 + 双方核对 6 位数字，之后用证书互相认证 |
| 离线补发 | 对方离线时内容排队，在有效期（默认 15 分钟）内回来会自动补发；过期的丢弃 |
| 自动更新 | 新版本发布后约 1 秒内收到通知并自动下载 |
| 命令行 | Windows 上 `cbridge`，可发送文本/文件、查看状态 |

不做：iOS/macOS/Linux 客户端、图片/富文本剪贴板、云端中转。

## 2. 使用前提

1. 所有要同步的设备都**安装并登录 Tailscale**，处于同一个 tailnet，保持连接。
2. Windows：64 位 Windows 10/11，已装 **.NET 10 桌面运行时（x64）**。
3. Android：8.0（API 26）及以上，64 位 ARM。

## 3. 安装

下载页（设备已连上 tailnet 时用浏览器打开）：`https://tony-ai-pc-1.tail9f7f1f.ts.net/clipbridge/`

**Windows**

1. 下载 zip，右键 → 属性 → 勾选“解除锁定”。
2. 解压到当前用户可写的文件夹（例如 `D:\Apps\ClipBridge\`，不要放 `Program Files`，否则无法自动更新）。
3. 运行 `ClipBridge.exe`。出现 SmartScreen 提示时点“更多信息 → 仍要运行”（程序没有购买代码签名证书）。
4. 首次监听时 Windows 防火墙可能弹窗，选择允许“**专用网络**”。设备之间只通过 Tailscale 地址直连。
5. zip 里还有 `cbridge.exe`（命令行，见第 9 节）。

**Android**

1. 下载 APK 并安装，系统会引导你允许“安装未知应用”。
2. 打开 ClipBridge，按首次引导操作：确认 Tailscale 已连接、允许通知；电池优化是可选项。

## 4. 配对（一次性）

两台设备都在线、都开着 Tailscale。

1. **电脑**：设备页 → “配对新设备…”，窗口显示二维码和配对链接（5 分钟有效）。
2. **手机**：设备页 → “配对新设备”，选一种方式：
   - **扫码**：扫描电脑上的二维码（需要相机权限）；
   - **粘贴链接**：把电脑上“复制链接”得到的 `clipbridge://pair?…` 粘贴进来；
   - **手动输入**：填电脑的 Tailscale 地址、端口、配对密钥（指纹可选；不填时务必核对下一步的数字）。
3. 手机显示一个 **6 位数字**，电脑弹出“配对请求”也显示一个数字。**两个数字必须一致**，再在电脑上点“允许”。不一致就点“拒绝”，不要继续——这说明连接可能被人拦截。
4. 双方显示“配对成功”。之后设备会自动连接，重启后也一样。

电脑之间同理：一台“配对新设备…”，另一台“加入配对…”。

解除配对：设备页 → “解除配对”（会通知对方并永久拉黑对方证书）。

## 5. 同步剪贴板

配对完成后**不需要再设置任何东西**：在任一设备上复制，内容会自动发到所有已配对的设备；对方在线且在前台/可写时直接写进它的剪贴板。（想关掉：电脑托盘菜单里取消“同步我复制的内容”，手机设置里关闭“自动发送我复制的内容”。）

### 电脑 → 其它设备

1. 在电脑上复制文字。电脑一直在监听剪贴板，所以**每次复制都会自动发给所有已配对的设备**（在设备页可以对某台设备关掉“自动发送”，例如只想收不想发的公用电脑）。
2. 对方是电脑：默认直接写入它的剪贴板（写入前会确认你没有在这期间又复制了别的东西，否则只通知）。
3. 对方是手机：应用在前台时直接写入；否则弹“收到的剪贴板”通知，点“复制”写入，点“忽略”丢弃。

### 手机 → 其它设备

Android 不允许应用在后台读取剪贴板，所以自动发送发生在**你打开 ClipBridge 的时候**：窗口获得焦点时检查一次剪贴板，如果有刚复制（5 分钟内）的新内容，就自动发到所有已配对的设备并提示“已发送给 N 台设备”。第一次安装后看到的剪贴板内容只记录、不发送。不想等到打开应用时，仍可以随时手动发：

- 在 ClipBridge 里点“发送剪贴板”；
- 在任何应用里选中文字 → 分享 → ClipBridge；
- 通知栏常驻通知上的“发送剪贴板”；
- 快捷设置磁贴“发送剪贴板”（先把磁贴添加到快捷设置面板）。

#### 后台自动发送（进阶，可选）

如果你不想每次都先打开 ClipBridge，可以开启**设置 → 后台自动发送（进阶）**。它使用 Android 的“悬浮窗取焦 + READ_LOGS”方案（与开源项目 ClipCascade 相同），需要 **Android 10 及以上**；Android 8/9 上开关是禁用的。

1. 开启实时模式（保持后台连接）。
2. 在系统设置里允许 ClipBridge “显示在其它应用上层”（悬浮窗）。
3. 用电脑执行一次（需要开启 USB 调试；授权后重新打开应用）：

   ```sh
   adb shell pm grant com.nightclip.app android.permission.READ_LOGS
   adb shell am force-stop com.nightclip.app
   ```

   设置页里可以一键复制这两条命令。**授权在更新和重启后保留，卸载重装后需要重做。**
4. 状态显示“运行中”后，在别的应用复制文本就会自动发送。

代价与限制：

- 每次后台读取会短暂取得窗口焦点，可能影响正在输入的键盘；Android 12+ 还会显示系统的“已粘贴”提示。
- 800ms 内连续复制只发送最后一条；第一次观察只记基线、不发送。
- 没有电脑、不能执行 ADB 时**不要开启**；原来的“打开应用时自动发送”仍然有效。
- 部分厂商系统会限制悬浮窗、日志或后台服务；如果状态一直不运行，关掉此功能即可回退到前台方案。
- 需要 Android 10 及以上；更老的系统只保留“打开应用时自动发送”。
- `READ_LOGS` 只用于读取 `ClipboardService` 的拒绝日志，不读取、不保存其它日志和剪贴板正文。

### 手动发送文字（三端相同，2026-10-28 起）

- **「发送文字」（设备页顶部；Android 是输入框）**：只发给**当前在线**、并且「自动发送」开着的设备。离线的设备不排队；一台都不在线时会提示「没有在线的设备，未发送」。
- **单独发给某一台设备**：在那台设备的卡片上点「发送文字…」，或者点「发送剪贴板」，就只发给它。即使它离线也会排队，等它上线后送达；它的「自动发送」开关不影响这种手动发送。

### 通知开关（三端都有）

在「设置 → 显示通知」里关掉后，收到内容、文件和更新时都不再弹提示。收到的内容照样进收件箱，配对窗口和接收文件的窗口照常出现。Android 开着实时模式时，系统要求的常驻通知仍会保留。

### 暂停、撤销与保护

- **暂停同步**：电脑托盘菜单“暂停同步”（15 分钟 / 1 小时 / 4 小时），手机设置里“暂停同步”。暂停期间本机既不自动发送，也不自动写入收到的内容（只通知）；到点自动恢复，也可以随时“恢复同步”。手动发送不受影响。
- **撤销**：电脑自动写入你的剪贴板后，托盘菜单“撤销上次自动写入”在 2 分钟内可以恢复写入前的内容（只保存在内存里，不写磁盘；来自密码管理器的内容不会被保存）。
- **只有刚复制的内容才会自动写入**：对方离线、休眠、网络慢而晚到（超过 20 秒）的内容只通知，不会覆盖你此刻的剪贴板，点“复制”才写入。
- **不会来回弹**：三台及以上设备时，一台设备写入的内容不会被它自己再广播出去，没有时间限制；你真正复制了别的内容之后才重新开始。

### 处理策略（每台设备单独设置）

| 策略 | 效果 |
| --- | --- |
| 只通知 | 弹通知，不改剪贴板 |
| 手动 | 通知，点“复制”后才写入 |
| 自动 | 直接写入剪贴板（**新配对的设备默认**）。电脑端写入前会检查你有没有又复制了别的东西，有则降级为通知；手机端只在应用处于前台时自动写入，否则降级为通知 |

在设备页调整每台设备；设置页可设“新设备的默认策略”。**升级前已经配对的设备保持原来的策略**，想让它们也自动写入，在设备页改成“自动”。

### 敏感内容

看起来像密码、令牌、私钥、一次性验证码的文本会被标记为**敏感**：通知和列表里只显示“敏感内容（已隐藏）”，点“显示”才展开；**永远不会自动写入**，即使策略是“自动”；想完全不发送这类内容，在设置里关闭“允许发送看起来像口令/令牌的内容”。

判断条件不是“只要含数字和英文”。对**单个词**（没有空格/换行，长度 8–128，不是 URL/路径）满足以下之一才会判为敏感：

- 至少三种字符类别（大写、小写、数字、符号），且至少有一个数字，例如 `Hello123`、`P@ssw0rd!2024`；
- 长度至少 24、至少两种字符类别、香农熵 > 3.6，例如长随机令牌；
- 私钥标记、已知令牌前缀（`ghp_`、`AKIA…`、`sk-…` 等）、JWT，或 6–8 位纯数字一次性验证码。

因此 `Hello123` 确实会被误判，`hello123`（只有两类）不会；普通句子、命令、URL、文件路径不会。这个启发式可以关闭：**设置 → 同步 → 自动识别敏感内容（口令/令牌）**（Windows 在设置页同一项）。关闭后本机不再隐藏、也不会因此阻止自动写入；密码库复制的内容仍然永远不会被自动发送。默认开启。

### 其它行为

- 刚写入的内容不会被当作新内容发回去（回声抑制）；一次复制触发多次通知也只发一次。
- 单条文本上限 64 KiB，更大的请作为文件发送。
- 带“排除监控”标记的复制（密码管理器），电脑端会忽略。
- 对方离线时内容排队，过期（默认 15 分钟，设置里可改 30–86400 秒）后丢弃；对方回来时补发的内容只通知、不自动写入。

## 6. 传文件

**发送**：电脑——设备页“发送文件…”选设备和文件（可多选），或把文件拖到设备卡片上；手机——设备页每张设备卡片上有：**“发送文件”**（任意文件）、**“图片/视频”**（系统相册选择器，照片和视频都可以，可多选）和**相机图标**（拍照并发送给这台设备）；也可以在文件管理器/相册里分享 → ClipBridge，选择目标设备；命令行——`cbridge file send --to 设备名 文件…`。

**拍照并发送（手机）**：设备页顶部“发送剪贴板”“配对新设备”旁边的相机图标按钮——只有一台设备可发时直接拍；有多台时先问发给哪一台（或“所有已连接的设备”）。点后进入系统相机，拍好确认就自动发出，对方照常要点“接收”。第一次会请求相机权限（和扫码配对共用同一个权限）。照片文件名是 `IMG_年月日_时分秒.jpg`；**不会存进相册**，只在应用缓存里留 24 小时（下次拍照时清理），所以拍之前先确认对方在线；发送失败了就得重拍。视频请用“图片/视频”从相册选，拍视频暂不支持一键发送。

**接收**：对方发来时弹出提示（文件名、大小、来自谁），**不会自动接收**。点“接收”才开始，“拒绝”则通知对方。进度、速度和取消在“传输”页（手机是通知）。

- 电脑保存到设置里的“接收文件的保存位置”（默认 `下载\ClipBridge`）；重名自动加 `(1)`，不会覆盖已有文件。
- 手机先收到应用私有目录，完成后保存到“下载/ClipBridge”并清理私有副本。
- 断线、重启应用会自动续传；收齐后核对校验和，不一致会删除并提示让对方重发。
- 空间不足时会拒绝，不会去删你的其它文件。
- 对方给的文件名会被清洗（去掉路径、非法字符、Windows 保留名），无法写到保存目录之外。

## 7. 各页面

**电脑**（左侧导航）

- **设备**：已配对设备、状态（已连接 / 正在连接 / 离线（排队 N 条）/ 需要重新配对 / 已解除）、重命名、策略、重新连接、解除配对、发送文件。
- **收件箱**：最近收到的文本，“复制”“忽略”，敏感条目折叠，“清空”。
- **传输**：文件传输的进度与历史。
- **密码库**：本机加密的密码、API 密钥、机密和笔记，见[“密码库（Windows）”一节](#14-密码库windows)。
- **设置**：同步开关、新设备默认策略、有效期、收件箱条数、是否允许发送敏感内容、开机自启、接收文件位置、更新、防火墙说明、关于。
- **诊断**：核心状态、监听地址、各设备游标；“没有找到 Tailscale 地址”横幅；复制诊断信息（不含密钥）、打开日志/数据文件夹。

**托盘**：左键打开窗口；右键菜单有“配对新设备…”“同步我复制的内容”“立即发送当前剪贴板”“开机自启”“检查更新”“锁定密码库”“退出”。**关闭窗口只是隐藏到托盘**，要退出请用托盘菜单。

**手机**（底部导航）：设备、收件箱、设置。设置里的**实时模式**（默认关）开启后常驻一条通知并保持后台连接，重启手机后自动恢复；关闭时只在应用运行期间同步。建议同时把 ClipBridge 从电池优化中排除，否则部分系统会杀掉后台。**后台自动发送（进阶）**在同一页，默认关闭；开启后显示悬浮窗、READ_LOGS、监听状态和触发计数。**密码库**一栏的“密码库页面防止截屏和录屏”默认开，开发排查时可临时关闭。

## 8. 更新

- 应用启动后保持与更新服务的连接，开发者一发布新版本，约 1 秒内收到。默认自动下载并校验（签名、大小、SHA-256），关闭“自动下载”后需手动点“下载”。
- **Android**：通知“ClipBridge 更新已就绪”，点按安装（首次需允许“安装未知应用”）。
- **Windows**：托盘气泡 + 任务栏闪烁，点“重启并更新”；安装失败会回滚并继续运行旧版本。
- 实时通知只在应用运行时有效（手机建议开实时模式）。

## 9. 命令行 `cbridge`（Windows）

需要 ClipBridge 正在运行。常用：

```text
cbridge status                          状态与设备
cbridge doctor                          检查 Tailscale 地址、配对和连接
cbridge clip send --text "你好"          发给所有设备（--to 设备名 指定一台；不带 --text 时读标准输入）
cbridge file send --to Pixel a.zip      发文件（--wait 等到完成）
cbridge inbox list | inbox show <id>    查看收件箱（敏感条目的正文只在界面里显示）
cbridge transfers                       传输列表
cbridge --json status                   机器可读输出
```

配对、解除配对、修改设置等涉及信任的操作**只能在界面里做**。详见 [api-spec.md](api-spec.md) §9（含退出码）。

## 10. 数据与隐私

- 数据目录：Windows `%LOCALAPPDATA%\ClipBridge\`；Android 应用私有目录。
- 数据库里的设备私钥、事件内容、剪贴板文本均加密；加密密钥由 Windows DPAPI / Android Keystore 保护（旧版本的明文密钥文件首次启动时自动迁移并删除）。
- 程序不向第三方发送数据；唯一的外联是向你自己的更新服务器检查和下载更新。
- 日志不记录剪贴板内容、配对密钥和密钥。
- **重置本机**：关闭程序，同时删除整个数据目录（Android：系统设置里“清除数据”）。会得到新的设备 ID，所有配对需要重做。**不要只删数据库或只删密钥文件。**

## 11. 常见问题

| 现象 | 处理 |
| --- | --- |
| 电脑显示“没有找到 Tailscale 地址” | Tailscale 未运行/未登录；启动并登录后几秒内自动恢复 |
| 设备一直“正在连接”/“离线” | 两端都要连着 Tailscale；防火墙是否允许“专用网络”；对方应用是否在运行（手机建议开实时模式） |
| 设备显示“需要重新配对” | 对方已不认识本机（被解除或重装）；解除配对后重新配对 |
| 配对时两边数字不一致 | 点“拒绝”，不要继续 |
| 手机收不到内容 | 通知权限是否打开；应用是否被系统杀后台；在设备页看状态 |
| 手机点“复制”没反应 | 少数系统限制后台界面写剪贴板；先打开 ClipBridge 再从收件箱复制 |
| 后台自动发送不工作 | 确认实时模式开、悬浮窗已授权、`READ_LOGS` 已用 ADB 授予并重新打开应用；看设置页的监听状态/错误；部分厂商系统不支持，关掉后回退前台方案 |
| 文件“校验失败” | 传输中文件被改动或损坏，让对方重发 |
| 更新失败 | 设备没连上 tailnet 或开发机离线；连上后手动检查更新 |

## 12. 建议你优先在真机上验证的地方

1. Windows：托盘图标与气泡；复制一次是否只发一次；从密码管理器复制是否被忽略；DPAPI 密钥迁移；防火墙弹窗；开机自启；更新后重启。
2. Android：扫码配对；通知上的“复制”“忽略”；分享菜单与快捷设置磁贴；实时模式在你的手机品牌上锁屏后的存活；接收文件保存到“下载”；**后台自动发送**（授权向导、在别的应用复制后是否自动发送、键盘是否被短暂打断、关掉后 `logcat` 是否停止）；密码库的解锁/自动锁定/防截屏/剪贴板清除；自动填充在 Chrome 与常用应用；密码库同步。
3. 两端：配对 → 双向同步 → 断网/休眠后恢复 → 大文件续传。

## 13. 密码库（Android）

> **请先知道：** 这部分界面目前只做过编译和自动化单元测试，**还没有在真机上运行过**。请先放一些不重要的内容试用，并按下面的办法留好备份。Android 自动填充见[第 15 节](#15-自动填充android密码库)；通行密钥**不在这一阶段**。

底部导航的“密码库”标签是一个加密的密码本：账号密码、API 密钥、单个机密（许可证、PIN）和安全笔记。数据保存在手机上，是标准的 KeePass（KDBX 4）文件，导出后可以用 KeePassXC 等软件直接打开；已配对设备默认自动同步完整加密副本，可在“设备同步”里单独关掉某台设备。

### 第一次使用

1. 打开“密码库”，设置**主密码**（也可以再加一个密钥文件，之后每次解锁都要同时提供它）。会有进度条提示强度；太弱只会警告，不会拦着你。
2. **忘记主密码就永远打不开密码库**，没有任何找回办法，开发者也帮不上忙。创建时必须勾选“我明白”才能继续。
3. 创建后会提示你立刻**导出一份加密备份**（可以跳过，但强烈建议做）。备份文件用你另设的密码加密，放在手机之外的地方最安全。
4. 手机较慢时，“高级选项”里的密钥强度会自动选“低”；解锁超过 3 秒就是慢。

### 日常使用

- **解锁**：输入主密码（和密钥文件）。连续输错 3 次后要等几秒才能再试，等待时间会翻倍，界面上有倒计时。
- **快速解锁**（可选，默认关）：解锁成功后会问你要不要用指纹或面容代替输入主密码。有效期可在密码库设置里选（默认 72 小时，可设永不）；重启手机、连续失败 5 次后仍要重新输入主密码；输错一次主密码、更换主密码或指纹有变动，快速解锁都会失效。
- **找条目**：顶部搜索框（搜标题、用户名、网址、备注、标签，不会搜到密码本身），下面的标签按类型筛选，还可以按分组看、看“即将到期”和回收站。
- **列表操作**：**点按条目本身自动复制密码**（复制后 20 秒清除，可在密码库设置改；没有密码的条目、回收站条目会打开详情）。每行右侧有独立的**眼睛（查看）**和**铅笔（编辑）**按钮，不会和复制混淆。
- **查看和复制**：条目详情里密码默认显示为圆点，点“显示”后 15 秒自动遮回；“复制”会把内容放进剪贴板，**20 秒后自动清除**（可以在“密码库设置”里改，或设为不清除）。复制的内容不会被同步到其它设备。
- **主密码/生物解锁有效期**：密码库设置里可以单独配置“空闲自动锁定”（含永不）和“生物解锁有效期”（默认从上次主密码解锁起 72 小时，可设为永不）；两者独立。无论生物解锁有效期多长，手机重启或连续失败 5 次后都要重新输入主密码。
- **一次性验证码**：条目里保存了 TOTP 密钥后，详情页会显示实时的 6 位验证码和倒计时。
- **新建和编辑**：右下角“＋”选择类型（账号 / API 密钥 / 机密 / 安全笔记）。API 密钥有“接口地址”“Key ID / Environment / Region”等现成字段和到期日。密码旁的“生成密码”可以生成随机密码或口令短语。有未保存的修改时离开会先问你。
- **附件**：每个条目可以附加文件（最大 5 MiB），也可以另存出来。
- **历史和回收站**：每次修改都会保留旧版本，可以恢复；删除先进回收站，在回收站里再删才是永久删除。
- **锁定**：右上角的锁按钮立即锁定；应用在后台超过设定时间（默认 30 秒，可设永不）、屏幕熄灭（默认开，可关）、空闲超过设定时间（默认 5 分钟，可设永不）都会自动锁定。锁定后列表、详情和剪贴板里复制的密码都会被清掉。
- 密码库页面**默认不能截屏，也不会出现在最近任务的缩略图里**。开发排查问题时可到“设置 → 密码库 → 密码库页面防止截屏和录屏”临时关闭（默认开）；关闭后这些界面里的密码和笔记可能被截屏、录屏或云备份获取，排查完请重新打开。自动填充的解锁/保存界面也受这个开关控制。

### 备份、导入和导出（右上角“更多”）

- **备份与恢复**：每次修改、删除、导入、恢复之前，密码库都会自动留一份快照；也可以点“立即备份”。每份备份可以“验证”（真的用密码打开一遍，确认能恢复）和“恢复…”：先**查看差异**，再选择只恢复选中的条目、合并，或整库替换（需要再次确认）。恢复前会先自动拍快照，所以恢复本身可以撤销。更换过主密码后，更早的备份需要输入**旧主密码**才能打开。
- **导入**：KeePass 文件（.kdbx，需要那个文件的密码）或 CSV（Chrome、Bitwarden、1Password、LastPass、KeePassXC 导出的表头都能认）。导入前会先自动备份。
- **导出**：加密的 .kdbx（用你现场设的新密码加密）或明文 CSV。明文 CSV 里的密码**没有任何保护**，界面有红色警告，只在迁移到别的工具时用，用完立即删除。两种导出都要再输入一次主密码。
- **更换主密码**：整个库用新密码重新加密；旧备份仍需要旧主密码，请先留着旧密码，直到这些备份不再需要。
- **健康报告**：列出弱密码、重复使用的密码、超过一年没换的密码和已过期的条目；只在手机本地检查，不联网。

### 设备同步（Android）

在“密码库”页右上角“更多”或“密码库设置”里打开“设备同步”（没有密码库、或密码库已锁定时，在新建页和解锁页也能进）。

- 只传输**加密的密码库文件**，对方没有主密码就读不了内容。**每台已配对设备默认自动同步，并保存一份完整副本**；没有中心节点，任何一台离线都不影响本机打开密码库，重新连接后自动合并。
- 连接只接受同一 tailnet 内、双方证书已配对（SAS 核对过）的设备；**配对就是密码库同步的信任决定**——与这台设备配对的设备会保存完整加密副本。右侧开关默认开，可以单独关掉某台设备；关掉只停止之后的同步，不会清除它已经拿到的内容。
- 在另一台设备上已经有密码库、而这台还没有时：配对并连接后，库会自动传过来，提示“已加入 xx 的密码库”，然后用**那个库的主密码**解锁（如果那个库用了密钥文件，解锁页可以选择密钥文件）。
- 如果对方是旧版本，可能仍显示“对方未开启”；把两端都升级到 0.1.61 或更高即可。
- 每台设备会显示连接状态、上次同步时间和当前状态：已是最新、等待解锁后合并、需要对方的主密码、需要你批准、对方未开启（旧版/被手动关掉）、同步出错。
- “需要对方的主密码”：对方更换了主密码，输入对方现在的主密码（一次性，不会保存）就能合并；输错了会留在原处让你再试。
- “需要你批准”：对方的库不是同一个库，或这一批修改会一次删除 5 个以上条目。读清说明后选“批准并合并”，不放心就选“忽略”（什么都不会改，请求还在）。需要处理的设备会在“更多”和“密码库设置”上显示红点。
- “立即同步”会马上试一次；平时每 15 秒自动检查，保存后立即推送。
- 关掉某台设备的开关，只是停止之后的同步，**不会清除它已经拿到的内容**。设备丢了或不再可信时，请同时**更换主密码**；撤销配对可以阻止它继续连接。
- 这部分同样**只做过编译和单元测试，没有在两台真机上跑过**。

### 这部分最需要在真机上确认的地方

屏幕截图是否真的被拦住；复制 20 秒后剪贴板是否清除（后台时能不能清）；锁屏和切到后台后是否自动锁定；指纹/面容快速解锁（含指纹变动后失效）；文件选择器的导入、导出、附件在你手机的文件管理器里是否正常；两台设备之间的同步、加入、批准和对方主密码的流程。

## 14. 密码库（Windows）

> **实话先说**：密码库的存储、加密、备份和恢复由 Go 核心实现，核心有自动测试，并且用 KeePassXC 命令行交叉检查过导出的文件。Windows 界面这一版**只在 Linux 上编译、并用逻辑测试和真实核心做了接口测试，没有在真正的 Windows 桌面上运行过**。下面写的是界面按设计应该有的行为，第一次使用请先放一些不重要的条目试试，并先做一次导出备份。手机上的密码库界面不在这一章。

### 它是什么

- 一个放在本机的加密文件（标准 KDBX 4 格式，保存在数据目录的 `vault` 文件夹），用**主密码**（可再加一个**密钥文件**）加密。KeePassXC、KeePassDX 等软件可以直接打开它，所以即使将来不用本程序，数据也不会被锁死。
- 条目有四种：**网站登录**（用户名、密码、网址、一次性验证码）、**API 密钥**（密钥、服务地址、Key ID / 环境 / 区域等自定义字段、到期日期）、**单个机密**（许可证、PIN、恢复码）、**安全笔记**。
- Windows 这一版**没有单独的密码库同步页面**；已配对设备默认自动同步，Windows 会作为完整副本参与（核心能力已具备）。密码库里复制出来的内容**不会**被自动同步到你的手机（即使“复制即同步”开着）。

### 第一次：创建

1. 左侧导航点“密码库”，会看到“创建密码库”。
2. 输入主密码两遍。下面的强度条是实时的；密码弱会提醒，但仍然允许你用。
3. **请认真看红框：主密码不保存在任何地方，也没有“找回密码”。忘记主密码（以及你选的密钥文件）= 密码库永远打不开。**
4. “高级选项”里可以选加密强度（低 / 标准 / 高）；老电脑选“低”。一般保持“标准”。
5. 如果选了密钥文件，**以后每次解锁都需要同一个文件**，丢了同样打不开。
6. 创建成功后会提示你立刻导出一份加密备份（用另外设定的密码加密）。可以跳过，但强烈建议做。

### 日常使用

- **解锁**：输入主密码（和密钥文件）回车。连续输错三次后需要等待一小会儿（1、2、4 秒…最长 5 分钟），按钮上会显示倒计时。
- **左边**：快速筛选（全部 / 网站登录 / API 密钥 / 机密 / 笔记 / 即将到期 / 回收站）和分组。**中间**：条目列表和搜索框（搜索标题、用户名、网址、备注、标签和自定义字段名；**不会**搜索密码等受保护的值）。**右边**：详情。
- **详情里的机密默认是遮住的**：点“显示”才展开，15 秒后或切换到别的条目时自动重新遮住。“复制”把内容放进剪贴板，并按“密码库设置”里的时间（默认 20 秒）自动清除——**只有剪贴板里还是刚才复制的那份时才清除**，你中途复制了别的东西就不会被清掉。复制的内容带有“不要进入剪贴板历史 / 不要上传云剪贴板 / 不要被监视”的标记，也不会被同步到其它设备。
- **一次性验证码**每秒刷新，圆环显示剩余时间；一段时间没有操作时会暂停刷新（否则它会让自动锁定永远不触发）。
- **打开网址**只接受 `http://` 和 `https://` 开头的地址，用默认浏览器打开。
- **新建 / 编辑**：按类型显示不同的输入框；密码框旁有“生成…”（长度 8–64，字符类别，避免易混淆字符，或口令短语）和实时强度。取消时如果有改动会先问你。
- **删除**先进回收站，回收站里再删一次才是永久删除；“清空回收站”和永久删除都会二次确认。每个条目保留历史版本，可在详情里“恢复到此版本”。
- **附件**：添加（单个文件最多 5 MiB）和“另存为…”。为了安全，保存时**不会覆盖**已有文件，遇到同名会自动换一个名字。
- **健康报告**：弱密码、重复使用的密码、很久没改的、已过期的。全部在本机计算，**不联网**，也不会查询泄露库。双击/“查看”跳到对应条目。

### 备份与恢复

- 每次保存、删除、导入、恢复、改主密码之前，程序都会自动拍一张加密快照（保留最近 20 张，再加每天、每周各一张）。“备份与恢复”里能看到它们的时间、原因和大小，也可以“立即备份”。
- **验证**：真的用密码把备份打开，告诉你里面有多少条目——“可以恢复”才算数。改过主密码之后，更早的备份需要**旧主密码**。
- **预览差异**：列出“只在备份里”“内容不同”“只在当前库里”的条目标题（不显示密码），然后选择：只恢复勾选的条目 / 合并 / 整库替换（需要输入“替换”二字确认）。恢复之前会先给当前库拍一张快照，所以恢复本身也能撤销。
- **导出**：加密的 KDBX（要再输一次主密码，并给导出文件设一个新密码）；CSV 是**明文**，会弹红色警告，要求输入“明文”二字并再次输入主密码，仅在必须迁移到别的软件时使用。**导入**：KDBX 文件（输入它的密码）或 CSV（Chrome/Edge、Bitwarden、1Password、LastPass、KeePassXC 等常见格式）。

### 自动锁定与防窥

- 无操作超过设定的秒数（默认 300 秒）自动锁定；可选“永不自动锁定”（核心不会因空闲锁定）；后台锁定默认 30 秒、熄屏锁定默认开，也都可以在密码库设置里关闭或设永不；锁屏、睡眠、切换用户、注销时也会立刻锁定；托盘菜单有“锁定密码库”，页面上有“立即锁定”。锁定时：列表、详情、搜索框全部清空，打开着的密码库对话框会被关闭（**正在编辑但没保存的内容会丢失**），剪贴板里还是我们写入的那份机密会被清掉。
- 密码库页面显示期间，窗口被设为“禁止截屏和录屏”（Windows 的排除捕获功能；可在“密码库设置”里关闭）。较旧的 Windows 上可能表现为黑块或不生效。
- Windows 上暂时**没有**“快速解锁”（指纹 / PIN 代替主密码），每次都要输入主密码。

### 没有做的事

自动填充、浏览器扩展、Windows 端的密码库同步界面、共享库、泄露检查（联网）。如果你需要在浏览器里自动填充，目前可以在电脑上另外安装 KeePassXC，直接打开同一个 `.kdbx` 文件（但**不要两个程序同时编辑同一个文件**）。

### 建议你在真机上先验证的

1. 创建 → 添加几种条目 → 锁定 → 解锁 → 故意输错三次看倒计时。
2. 复制密码，粘贴到别处；等 20 秒确认剪贴板被清空；复制后再自己复制别的东西，确认它**没有**被清掉。
3. Win+V 剪贴板历史里**不应该**出现密码库复制的内容。
4. 用截图工具 / 录屏工具截取密码库页面，应该是黑的或空的。
5. Win+L 锁屏再回来，密码库应处于锁定状态。
6. 导出一个 KDBX，用 KeePassXC 打开；做一次备份、改一个条目、预览差异并恢复。

## 15. 自动填充（Android，密码库）

> **请先知道：** 自动填充只做过编译和自动化单元测试，**还没有在真机上运行过**。请先用不重要的账号试用，并保留密码库的备份。通行密钥（Passkey）**不在这一阶段**。

**启用：** 在 ClipBridge 的设置里点“启用自动填充”，系统会问“要把 ClipBridge 密码库设为自动填充服务吗？”，选择确定即可（也可以去系统设置 → 密码和账号 → 首选服务）。启用后，在登录页面点用户名或密码输入框，下方会出现要填充的条目。

**怎么用：**

- 密码库已锁定时，弹出一行“解锁以填充”，输入主密码即可，成功后会列出匹配的条目；点一个就填入。
- 最多列出 5 个条目，最匹配的在前；每一行只显示标题和用户名，不显示密码。
- 没有匹配的条目时，只出现一行“打开 ClipBridge 密码库”。
- 页面要求验证码（两步验证）且条目里设置了 TOTP 时，会列出该条目；点选的一刻才生成当前验证码。
- 提交登录后，系统会问是否“保存到密码库”：可以确认或修改标题、用户名、网址再保存；如果同一个账号已有条目但密码不同，会问是否更新（旧密码保留在历史里）。
- 设置里的“每次填充前验证主密码”：开启后每次填充都要重新输入主密码。

**匹配规则：** 网页只按浏览器报告的域名匹配（同一个“主域名”才算，名字相似的不算，比如 `example.com.evil.net` 不会匹配 `example.com`）；应用按包名匹配（条目网址写 `androidapp://包名`，或自定义字段 `AndroidApp`）。`http://` 页面不会填充保存为 `https://` 的条目。浏览器如果没有报告域名，就不会提供任何填充。

**哪些浏览器：** Chrome 135 及以上、Firefox 等直接支持第三方自动填充服务；更老的 Chrome 需要在 Chrome 设置里启用“第三方自动填充”（或系统的兼容模式），否则网页里看不到候选项。ClipBridge 自己的界面不会被填充。应用里嵌入的网页（WebView）每次都会要求输入主密码。

**不做的事：** 不读剪贴板，不使用无障碍服务，不联网，不缓存密码；自绘界面或关闭了自动填充的应用里不会出现候选项。

**还没验证的：** 各品牌系统下下拉框的样子与位置、Chrome/Firefox 是否报告网页协议（`http`/`https`）、保存提示在不同系统版本上的行为、从后台解锁之后的自动上锁时间。遇到问题请告诉我具体的应用或网站。
