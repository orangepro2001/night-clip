# ClipBridge 使用说明书

> 版本：与 0.1.7 对应（2026-10-26）。**这是开发早期版本**：下面第 1 节列出了现在真正能做的事。第 8 节是计划中的完整用法，**尚未实现**，请不要按它操作。

## 1. 先看这里：现在能做什么，不能做什么

ClipBridge 的目标是在你自己的 Windows 电脑和 Android 手机之间同步剪贴板、传文件，设备之间直连，不经过任何第三方服务器。

| 功能 | 现状 |
| --- | --- |
| 安装并启动 Windows / Android 应用 | ✅ 可用 |
| 每台设备有稳定的身份（设备 ID，重启不变） | ✅ 可用 |
| 数据库与私钥在本机加密保存 | ✅ 可用 |
| 自动检查、下载、安装更新 | ✅ 可用（见第 5 节） |
| 设备配对 | ❌ 未开发 |
| 剪贴板同步（文本） | ❌ 未开发 |
| 文件传输 | ❌ 未开发 |
| 托盘图标、通知、历史记录、设置页 | ❌ 未开发 |

所以现在装上它，你会看到一个**状态页**：设备名、设备 ID、核心是否正常，以及更新栏。复制粘贴不会被同步，这不是故障，是还没做。

开发顺序是：设备间连接 → 配对 → 剪贴板同步 → 文件传输 → 完整界面。

## 2. 使用前提

- 所有要同步的设备必须在**同一个 Tailscale 网络（tailnet）**里，并且都已登录 Tailscale。这是产品设计前提：设备间直接用 Tailscale 地址互联，不需要自己的服务器，也不需要端口映射。
- 现在这个版本的状态页本身不需要联网；**自动更新**需要设备能访问你的 tailnet（更新包由开发机提供）。

## 3. 安装

### 3.1 Android（手机）

下载页（手机已连上 tailnet 的情况下用浏览器打开）：

- 下载页：`https://tony-ai-pc-1.tail9f7f1f.ts.net/clipbridge/`
- 直接下载 APK：`https://tony-ai-pc-1.tail9f7f1f.ts.net/clipbridge/v1/android/download`

步骤：

1. 下载完成后点击 APK 安装。系统会提示“出于安全考虑，不允许安装来自此来源的未知应用”，点**设置**，打开“允许来自此来源”（来源就是你用的浏览器），返回继续安装。
2. 如果系统的“Play 保护”提示该应用未知，选择“仍要安装”。这个应用没有上架应用商店，是你自己的开发者签名。
3. 安装后打开 **ClipBridge**。

要求：Android 8.0（API 26）及以上，64 位 ARM 手机（也含 x86_64 模拟器）。

### 3.2 Windows（电脑）

- 直接下载 zip：`https://tony-ai-pc-1.tail9f7f1f.ts.net/clipbridge/v1/windows/download`

步骤：

1. **先安装 .NET 10 桌面运行时（x64）**。这个程序依赖它，没有它会直接闪退或提示缺少运行时。
2. 对下载的 zip **右键 → 属性 → 勾选“解除锁定” → 确定**（否则 Windows 会给里面每个文件打上“来自网络”的标记）。
3. 解压到一个**当前用户可写**的文件夹，例如 `D:\Apps\ClipBridge\`。不要放进 `C:\Program Files`，否则自动更新写不进去。
4. 双击 `ClipBridge.exe`。
5. 如果出现“Windows 已保护你的电脑”（SmartScreen）：点**更多信息 → 仍要运行**。因为程序没有购买代码签名证书，这个提示是正常的。

要求：64 位 Windows 10 / 11。

## 4. 界面说明

### 4.1 Windows 窗口

从上到下：

1. **状态行**：`设备名 · 设备 ID`。设备 ID 形如 `dev_xxxxxxxxxxxxxxxxxxxxxxxxxx`，是这台电脑的唯一身份。
2. **日志框**：显示核心启动状态和收到的事件（`status`、`event ...`）。排错时把这里的内容复制出来。
3. **更新栏**：当前更新状态、进度条、一个操作按钮、“Download updates automatically”开关。
4. **Refresh status** 按钮：重新读取状态。

关闭窗口即退出程序（还没有托盘，不会驻留后台）。

如果是自己从源码编译的开发版，更新栏会显示 “Development build: updates are off”。

### 4.2 Android 界面

从上到下：

1. **ClipBridge** 标题和一段状态 JSON（设备名、设备 ID、平台、端口等）。
2. **Refresh status**：重新读取状态。
3. **Start connected mode**：启动前台服务，让核心在后台保持运行，通知栏出现常驻通知“Connected mode is on”。现在它还不会同步任何东西；以后连接配对设备就靠它。目前没有“停止”按钮，要停止请在系统设置里“强行停止”该应用。
4. **Updates** 卡片：更新状态、进度条、操作按钮、自动下载开关。

通知权限：Android 13 及以上需要在系统设置里手动给 ClipBridge 打开“通知”，否则常驻通知和“更新已就绪”通知不会显示（应用现在不会主动弹出授权窗口）。

## 5. 更新

应用会自己检查更新：

- 启动后约 20 秒检查一次，之后应用会保持与更新服务的“监听”连接：开发者一发布新版本，约 1 秒内就会收到。服务不可达时自动退避重试，离线时不会打扰你。
- 实时通知只在应用运行时有效：Windows 程序开着时；Android 点了 **Start connected mode**（前台服务）或界面开着时。
- 收到新版本时：Android 通知栏出现“update ready”（自动下载关闭时是“update available”）；Windows 任务栏图标闪烁。
- **自动下载**默认开启：发现新版本就在后台下载，校验通过后提示“已就绪”。关闭开关后，发现新版本会停在“可下载”，需要你点 **Download**。
- 每个更新包在安装前都会校验：发布签名（Ed25519）、大小、SHA-256。校验不通过的包不会被安装。

安装更新：

- **Android**：状态变成 “Version x.y.z is ready to install” 后点 **Install update**。系统安装器会弹出，点“更新”。首次可能先被带去设置页允许“安装未知应用”，允许后返回再点一次。
- **Windows**：点 **Restart and update**。程序会关闭、替换文件，然后自动重新打开。如果替换失败，会回滚并继续打开旧版本，同时弹出提示。

“必须更新”：状态文字会带 “(required)”，表示开发者把它标记为强制，旧版本应尽快更新。目前不会阻止你使用。

手动检查：点 **Check for updates**。

## 6. 数据在哪里、怎么重置

| 平台 | 数据目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\ClipBridge\` |
| Android | 应用私有目录 `files/clipbridge/`（卸载应用时一起删除） |

里面有：

- `clipbridge.db`：加密数据库（设备身份私钥、以后的配对信息和历史）。
- `devkey.b64`：数据库密钥。**这是临时方案**：密钥以明文文件保存，靠 Windows 用户目录权限 / Android 应用沙箱保护；以后会改成 Windows DPAPI 和 Android Keystore。
- `updates\`（下载的更新包）、`staging\`（Windows 安装更新时的暂存，下次启动自动清理）。

**不要只删其中一个文件。** 只删 `devkey.b64` 会让数据库永远打不开；程序发现密钥文件损坏时会报错而不是自作主张重建，就是为了防止这种情况。

重置这台设备：关闭程序，**同时**删除整个数据目录（Windows 删 `%LOCALAPPDATA%\ClipBridge\`；Android 在系统设置里“清除数据”）。下次启动会生成新的设备 ID。以后有配对后，重置会使这台设备需要重新配对。

隐私：程序不联网上传任何数据；现在唯一的网络访问是向你自己的更新服务器检查和下载更新。

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| Windows 双击没反应 / 立即退出 | 没装 .NET 10 桌面运行时；或 zip 没解压完整（`clipbridge_core.dll` 必须和 `ClipBridge.exe` 在同一文件夹） |
| 状态行显示 “Core failed to start”，日志里有错误 | 看日志框里的错误码：`KEY_INVALID`=密钥文件与数据库不匹配（见第 6 节）；`DB_UNAVAILABLE`=数据目录不可写或被占用，换用户可写目录；`INIT_FAILED` + `data_dir`=数据目录异常 |
| 更新栏显示 “Update failed: ...” | 设备没连上 tailnet / 开发机离线 / 服务不可达。连上 Tailscale 后点 **Check for updates** |
| 更新栏显示 “Update failed: manifest: signature is not from a trusted release key”（或其它以 `manifest:` 开头的消息） | 服务器上的更新信息签名不被信任。不要忽略：可能是服务器被篡改或配置错误，联系开发者 |
| 更新栏显示 “Update failed: … does not match the published SHA-256” | 下载损坏，应用已丢弃坏文件；再点一次 Download |
| Android 点安装没有反应 | 还没给 ClipBridge 开“安装未知应用”，或下载的文件已被清理；回到 App 再点 **Check for updates** |
| Android 安装更新提示“与已安装的应用签名不一致” | 你装的是调试版或来自别处的包。先卸载再装下载页的正式包（数据会丢，设备 ID 会变） |
| Android 没有通知 | 系统设置里给 ClipBridge 开通知权限 |

## 8. 计划中的用法（尚未实现，仅供了解）

以下来自设计文档（`architecture.md` §3、§6、§7），**现在的版本里没有这些功能**。

**配对（一次性）**

1. 在 Windows 点“配对”，窗口显示二维码（5 分钟有效）。
2. 在手机扫码；也可以手动输入地址、端口和一次性口令。
3. Windows 弹出确认：“与 **Pixel** 配对？校验码 **482 913**”，手机同时显示同一串校验码。两边一致再点“允许”。
4. 双方保存对方的证书指纹，之后连接用双向 TLS 认证，不在配对列表里的设备连不上。可随时在列表里撤销某台设备。

**剪贴板**

- 电脑上复制文字 → 手机收到通知 → 点“复制”写入手机剪贴板（默认不自动写入，避免覆盖你正在用的内容）。
- 手机上通过分享、通知动作或“发送剪贴板”把文字发到电脑。Android 系统不允许后台应用随意读取剪贴板，所以手机发出需要你主动触发一次。
- 每台对端可单独设置：只通知 / 手动应用 / 自动应用。看起来像密码或令牌的内容永不自动应用，通知里也不显示正文。
- 对方离线时事件会保留一段时间，对方回来后自动补发；过期的会丢弃，同一条消息不会重复应用。

**文件**

- 选文件 → 选目标设备 → 对方确认接收 → 传输，支持断点续传，完成后校验 SHA-256。
