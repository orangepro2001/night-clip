# 字符级 CRDT 评估（Phase 2，仅评估）

> 结论先行：**现在不采用**。块级三路合并 + 块内按行合并 + 冲突副本已经满足"不丢内容"，并且保持 Markdown 为唯一权威存储。下面记录评估依据，以及什么情况下应当重新考虑。
> 相关：[ADR-001](adr/001-notes-sync-and-storage.md) 替代方案、[sync-model.md](sync-model.md) §4。

## 1. 要解决的问题

两台设备在同步前**对同一行（同一句话）**做了不同的编辑。当前行为：较新的一份成为正文，较旧的一份保存为冲突副本，用户事后裁决（保留 / 换用副本 / 合并）。不丢内容，但需要人工处理。

在加入块内按行合并之后，下面这些常见情形已经**不会**产生副本：改不同的段落、改清单里不同的项、勾选不同的待办、同一段落里改不同的行、各自在末尾追加。

仍然会产生副本的：同一行被两边改成不同内容（包括同一个词）；一边删除某行、另一边改同一行；一边把一块拆成多块、另一边改它。

## 2. 候选方案

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| 字符级文本 CRDT（RGA / Yjs 类 / Automerge 文本） | 每个字符（或一段）有唯一 id，编辑是对 id 的插入/删除操作，合并天然无冲突 | 同一行内的并发编辑也能自动合并；可做实时协作 | 见 §3 |
| 词级 / 句级三路合并 | 在块内按词（CJK 按字）做 diff3 | 实现小、仍是纯函数、不改数据模型；多数"同一行改不同词"能合并 | 合并结果可能语法上拼出怪句子，也可能破坏行内标记（`**`、链接）；需要保护措施 |
| 保持现状 | 块 + 行 | 已实现并有收敛性证明 | 同一行并发编辑要人工裁决 |

## 3. 为什么 CRDT 与本模块的约束冲突

1. **权威存储是 Markdown 文本**（ADR-002）。CRDT 的权威状态是"带 id 的字符序列 + 墓碑"，Markdown 只是它的视图。要么两份状态（必然漂移，ADR-002 已经否决），要么存储格式改成 CRDT 状态，导出再生成 Markdown——"数据可移植、用任何编辑器打开"的退出成本就变了。
2. **修订按内容寻址**（`rev_id` = 规范化正文哈希）。CRDT 的同步单位是操作而不是快照；操作 id 与内容无关。现有的修订图、确定性合并修订、冲突副本的内容寻址 id 都要重新设计。
3. **规范化**（Markdown → 规范形式）是对整篇文本的变换。对 CRDT 来说，规范化会产生"全篇替换"的大批量操作，破坏意图保留；不规范化又会让同一内容在两端字节不同。
4. **编辑器必须产生细粒度操作**。当前两端是"整块文本 → 保存修订"；CRDT 需要输入法组合输入、撤销、选区替换等都映射成操作，Windows `TextBox` 与 Compose `BasicTextField` 都不给这个钩子，需要自己做 diff 或换编辑器。
5. **墓碑与历史膨胀**：文本 CRDT 的元数据通常比正文大一个数量级，且难以压缩（压缩需要所有设备的因果水位——正是我们尚未实现的那部分，见 sync-model.md §8）。
6. **库**：Go 核心、Android（gomobile）、Windows（C ABI）三处都要有同一实现。Go 里没有我们能直接依赖的、许可证和维护状态都合适的成熟库；自己写文本 CRDT 并证明收敛是一个独立的大项目。

## 4. 值得先做的中间步骤（若冲突副本仍然困扰用户）

**词级回退合并**：块内按行合并失败、且两边改的是同一行时，再对这一行做词级（CJK 按字）三路合并；只对 `paragraph` / 列表项文本这类行内内容尝试，标题、表格行、代码行不尝试；合并后用现有的 `Normalize` 校验，且要求结果的行内标记（`*`、`_`、`` ` ``、`[`、`]`、`(`、`)`）配对数与两边之一相同，否则放弃、仍然产生副本。它仍是 `merge3` 的纯函数，对称性和收敛性的证明方式不变。

不现在做的原因：缺少真实使用数据说明"同一行并发编辑"有多常见；多设备并发编辑同一行本来就少见，而一个拼接出来的句子用户可能没发现问题——比副本更隐蔽。应当先看真机使用中冲突副本的数量与类型。

## 5. 重新考虑 CRDT 的触发条件

任何一条出现，就重新评估（并且先做 §4）：

- 真实使用里冲突副本频繁，且主要是同一行内的编辑；
- 要做**实时多人协作**（同一时刻多个光标）——这是 CRDT 真正不可替代的场景，但不在本产品范围内（笔记只在用户自己的设备之间同步）；
- 出现一个许可证宽松、被两端运行时都验证过的文本 CRDT 实现，且能让 Markdown 文本仍然是权威、可导出的存储。
