# notes ADR-002：以 Markdown 为权威的富文本 + Markdown 双格式编辑

- 状态：**Accepted**（2026-10-27 起草；同日核心的 Markdown 规范化、块模型与渲染树落地并有自动化测试。编辑器 MVP 为"源码编辑 + 实时预览"，所见即所得块编辑器仍是 Phase 2）
- 日期：2026-10-27
- 决策者：待定（项目组）
- 相关文档：[editor-and-markdown.md](../editor-and-markdown.md)、[architecture.md](../architecture.md)、[ADR-001](001-notes-sync-and-storage.md)

## 背景

需求是"支持富文本编辑器和 Markdown"。两端技术栈不同：Windows 用 WPF，Android 用 Kotlin Compose。若两端各自选用富文本控件并以 HTML/私有格式存储，会陷入：

1. 两端渲染与语义漂移；
2. 富文本 ↔ Markdown 双向转换丢信息且难以审计；
3. 同步时无法区分"渲染差异"与"内容差异"，制造误冲突（见 [ADR-001](001-notes-sync-and-storage.md)）。

同时用户希望"富文本编辑器"的体验是所见即所得，而不是被迫写方括号星号。

## 决策

1. **Markdown 文本是唯一的权威存储格式**：每篇笔记的正文即规范化 Markdown（`body_norm`）。不存在第二份富文本真源。
2. **渲染与编辑分离**：核心把 Markdown 解析为**块模型**（稳定块 id），并通过 `notes.render` 输出结构化渲染指令；壳负责样式与交互，**不重写语义**。
3. **两端都编辑 Markdown**：MVP 采用"源码编辑 + 实时预览"（或注释列表条），Phase 2 升级为按块的所见即所得编辑器——但底层始终是 Markdown 文本。
4. **规范化是规范的一部分**：行尾/列表符/强调符/代码围栏/表格对齐等有一份确定性规则，跨端字节一致，是 `rev_id` 哈希的基础（[editor-and-markdown.md](../editor-and-markdown.md) §2）。
5. **支持 CommonMark + GFM 子集**；不支持的语法（内联 HTML、脚注、数学、自定义容器）以"未知块"保留原文，不执行、不丢弃。
6. **第三方编辑器库只能用于展示/输入**：它输出的内容必须回传为 Markdown，不能成为格式权威。
7. **粘贴转换要提示**：从外部粘贴 HTML 时经宽松降级为 Markdown，无法转换的部分明确告知用户，不静默丢弃。

## 替代方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 富文本（HTML/RTF）为权威 | 不采用 | 两端渲染不一致、无法可靠导出 Markdown、同步冲突判断困难 |
| 双格式（富文本 + Markdown 各存一份，双向同步） | 不采用 | 两份真源必然漂移，等价于持续冲突 |
| 纯源码编辑器，不做富文本 | 不采用（但作为 MVP 的起点） | 不满足"富文本编辑器"需求 |
| WebView + 同一套 JS 编辑器（两端一致） | 备选 | 一致性最好，但引入 WebView 运行时；若 WPF 与 Compose 各自的块编辑器成本超预期可切换 |
| 自研两端块编辑器 | 推荐（先源码，后块编辑） | 与核心块模型一一对应，无额外运行时 |

## 结果

### 正面

- 数据可移植（退出成本 = 一堆 `.md` 文件），用户可用任意编辑器打开。
- 同步基于字节规范化，渲染差异不会制造冲突。
- 块模型同时服务"所见即所得"与"块级合并"两个目标。

### 负面

- 富文本控件必须受约束（不能自由引入专有格式节点），可能牺牲部分排版能力（如任意定位、复杂表格合并单元格）。
- 规范化规则需要精确实现与大量语料测试，任何漂移都会触发同步问题。
- MVP 的"源码 + 预览"仍不是纯所见即所得，需向用户说明阶段性限制。

## 实施状态

- ✅ 核心：`core/notes/markdown`（规范化、块切分、块 id、渲染树；含幂等性/往返属性测试与模糊测试）。
- 🟡 编辑器选型（P0-4）结论：两端 MVP 都用**自研的源码编辑 + 核心渲染树预览**，不引入第三方控件、不引入 WebView。Windows 与 Android 的具体界面见 [development-plan.md](../development-plan.md) §8。
- ⛔ 所见即所得的块编辑器、粘贴 HTML 降级为 Markdown 的提示：Phase 2。
- ❓ IME 组合输入下的修订风暴：两端都用"最后一次编辑后 500 ms 静默再提交"；真机输入法行为未验证。
